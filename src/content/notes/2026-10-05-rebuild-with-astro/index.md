旧サイト「Stardust✨のおもちゃ箱」を閉じて、このサイトを一から作り直した。その記録。

## 何を決めたか

作りはじめる前に、まず「このサイトは何のためにあるのか」を決めた。

| 項目 | 決めたこと |
| --- | --- |
| 目的 | 自己紹介、作ったものの置き場、Web3 での身元の証明、Web3 の実験場 |
| 見る人 | Web3 のコミュニティ |
| 名前 | `stardust.box`（ENS と DNS がひとつになったドメイン。取り戻した話は[こちら](/notes/2026-10-05-recover-stardust-box/)） |
| 置き場所 | GitHub Pages |
| 作り方 | Astro |
| 旧サイトの記事 | 移さない。新しく書く |
| 書く立場 | 観察者 |

最後の「観察者」がいちばん大きな変化かもしれない。旧サイトのトップには「インターネットを取り戻す」という宣言を書いていた（いまもトップに残してある）。新しいサイトでは、Web3 で起きることを良いことも悪いことも、少し離れたところから記録していく。

### 土台は普通のサイトにする

「Web3 のサイト」といっても、ウォレットを持っていない人が読めないのでは困る。Web3 がこの先どうなるかも分からない。

そこで、**土台はふつうの静的なサイトにして、Web3 の機能はあとから「外せる形で」足していく**ことにした。Web3 の部分が動かなくなっても、文章は残る。

### 自宅のサーバーでは公開しない

自宅にもサーバーはある。ただ、そこで公開すると、家のネットワークを外に開くことになる。ほかの大事なサービスと同じ機械なので、やめた。動くもの（dapps の実験など）が必要になったら、自宅とは切り離した場所を借りる。

## なぜ Astro なのか

旧サイトは Jekyll（Ruby で動くサイトのツール）の研究者向けテンプレートで作っていた。使わない機能が多く、ブログとしては重かった。

Astro を選んだ理由は「アイランド」という考え方にある。

- ページの大部分は、JavaScript を使わないふつうの HTML（動かない海）
- 動きが必要な部品だけ、そこだけ JavaScript を読み込む（動く島）

ウォレットの接続ボタンのような Web3 の部品を、島として置ける。島を外しても、ページはそのまま残る。「Web3 の機能は外せる形で足す」という方針に、そのまま合っていた。

ほかにも、

- `src/pages/onchain.astro` を置けば `/onchain/` になる（ファイルの置き場所がそのまま URL）
- Markdown の記事を「コンテンツコレクション」でまとめて管理でき、書き間違い（日付の形など）をビルドのときに教えてくれる

といったところが、ブログに向いている。使ったのは Astro 7.3.5。

## 作ったもの

ページは 5 つから始めた。

| ページ | 中身 |
| --- | --- |
| Home | 自己紹介と最近の記事 |
| Notes | 観察の記録（このブログ） |
| Projects | 作ったもの |
| Onchain | オンチェーンの身元（名刺用のウォレットを用意したら載せる） |
| Lab | Web3 の実験 |

ブログとして最低限ほしいものも入れた。

- **下書き**: 記事に `draft: true` と書くと、手元の確認用のサーバーでは見えるが、公開されるサイトには出ない
- **タグ**: `/tags/` から記事を探せる
- **RSS**: `/rss.xml`。Web3 の人は RSS リーダーを使う人も多い
- **サイトマップ**: 検索エンジン向け
- **OGP**: X や Discord で共有したときに、タイトルと説明が出る

下書きの仕組みは数行で書ける。

```ts
const notes = await getCollection('notes', ({ data }) =>
  import.meta.env.PROD ? !data.draft : true,
);
```

公開用のビルド（`PROD`）のときだけ、下書きを外している。

## つまずいたところ

### GitHub Pages が勝手に Jekyll で動きはじめた

GitHub Pages には公開の方法が 2 つある。

- 旧来の方式: GitHub が Jekyll でビルドする
- GitHub Actions の方式: 自分で決めた手順（ここでは Astro）でビルドする

Astro を使うので後者にするつもりだった。ところが、`<ユーザー名>.github.io` という名前のリポジトリは、**push したとたんに GitHub が旧来の方式で Pages を有効にした**。そのままだと、Astro のソースを Jekyll でビルドしようとしてしまう。

公開の方法を切り替えて、走りはじめていた旧来の方式のビルドを止めた。

```bash
gh api -X PUT repos/<ユーザー名>/<ユーザー名>.github.io/pages -f build_type=workflow
```

公開には、Astro が用意している GitHub Actions（`withastro/action`）を使っている。`main` に push すれば、1 分ほどで公開される。

### 下書きは「非公開」ではない

GitHub の無料のプランで Pages を使えるのは、公開リポジトリだけだ。つまり、**`draft: true` の記事も、GitHub でソースを見れば誰でも読める**。下書きは「サイトに出ない」だけで、「秘密」ではない。人に見せたくない文章は、手元に置いておく。

同じ理由で、公開する前に、内部の情報（自宅のネットワークのアドレスなど）が混ざっていないかを毎回確かめることにした。

### Node.js を入れ直した

Astro は Node.js で動く。最初はよく使われる nvm で入れたが、Python をすでに anyenv（言語ごとのバージョン管理ツールをまとめるツール）で管理していたので、そろえるために nodenv に入れ直した。いまの Astro は Node.js 22.12 以上が必要で、24 を使っている。

## アクセス解析は Google Analytics にしなかった

アクセス数は知りたい。ただ、Google Analytics にはしなかった。

- Cookie を使って読む人を追いかけ、その情報が Google に送られる。「観察者」のサイトが読む人を追いかけるのは、なんだか違う
- そもそも、Brave は初期設定で Google Analytics をブロックする。広告ブロッカーを使う人の分も数えられない。Web3 の人が読むサイトだと、かなり少なく出るはずだ

代わりに、Cookie を使わない **Cloudflare Web Analytics** を使うつもりでいる（まだ入れていない）。ただ、これも計測用のスクリプトがブロックリストに入っていることが多く、Brave などでは数えられない可能性がある。ブロックされない計測をするなら、サーバーの側で数えるしかない。いまは「だいたいの傾向が分かれば十分」と割り切っている。

## これから

足していきたいものは多い。

- OGP の画像（共有したときに、大きな画像で出るように）
- Cloudflare Web Analytics
- Web3 の機能: 投げ銭、ウォレットでのログイン、記事を NFT として集められるようにする、など。まずはテストネットで試す
- サイトそのものを IPFS にも置いて、`stardust.box` の ENS からも開けるようにする

ひとつ足すたびに、ここに記録していく。

## 観察メモ

- 「Web3 のサイト」を作ろうとして最初に決めたのは、Web3 ではない部分（ふつうの HTML で読めること）だった
- Astro のアイランドは、「いつか外すかもしれない機能」を足すのに向いている
- 公開リポジトリで作るブログは、下書きまで含めて公開されている、と思っておくほうがいい
